## 1. 产品目标

管理员创建节点分组与套餐，在用户管理中创建账号并分配套餐。订阅用户登录后，只查看自己的服务、流量、有效期、可用节点与订阅信息。

基本规则：

- 业务中的“用户”统一指订阅用户。
- 管理员负责后台管理，和订阅用户分开入口、菜单与权限。
- 一个订阅用户拥有自己的登录账号、订阅凭据与流量记录。
- 多个用户可以使用同一个套餐，但不能共用订阅凭据或混算流量。
- 目标关系为：节点 → 节点分组 → 套餐 → 用户。
- “用户分组”用于用户分类；“节点分组”用于组织套餐中的连接资源，两者不能混用。
- 兼容现有用户与订阅链接，迁移前核对数据，不能仅凭旧角色名称推断账号用途。

## 3. 计划中的导航结构

### 管理后台

- 总览：服务运行状态、待处理问题、用户与套餐概况。
- 用户管理：创建账号、查看服务、分配套餐、续期、停用、重置密码。
- 订阅套餐：套餐内容、使用人数、版本与同步状态。
- 节点管理：服务器节点、节点分组、连接入站、节点监控。
- 系统设置：管理员账号、安全设置、订阅设置和通知设置。
- 高级配置：出站、路由、Xray 配置、API 文档。

用户分组、主机管理等已有功能保留，结合实际用途归位，不直接删除。

### 订阅用户端

- 我的首页：当前套餐、剩余流量、到期时间、服务状态。
- 我的订阅：复制订阅链接、格式说明、导入指导。
- 可用节点：仅展示该用户有权使用的节点及可提供的状态。
- 个人中心：账号信息与可支持的账号操作。
- 使用教程：按设备展示实际可执行的步骤。

管理员菜单不再把“我的首页”与后台系统总览并列；如需要用户视角预览，应提供明确的预览入口，避免身份混淆。

## 4. 分阶段实施任务

### P0：统一账号和主流程

- [x] **P0-01 账号盘点与兼容方案**：检查管理员、旧 user、自定义角色、customer 与客户端记录的关联；列出无法自动迁移的情况。
- [x] **P0-02 收敛身份模型**：产品界面只呈现管理员与订阅用户；移除不再需要的普通后台用户和自定义角色创建流程。
- [x] **P0-03 整理导航**：调整后台账号入口，区分系统总览与用户首页，统一菜单名称、图标、高亮和页面标题。
- [ ] **P0-04 合并用户操作**：创建用户一次完成账号与套餐配置；已有用户通过统一详情查看账号和服务，减少独立弹窗之间来回切换。
- [ ] **P0-05 兼容旧数据和链接**：保留旧订阅地址、凭据、流量和有效期；无法自动关联的记录进入待处理列表，不自动提权或删除。

验收标准：新管理员能完成“创建套餐 → 创建用户 → 用户登录”；订阅用户无后台入口，且直接请求后台接口也会被拒绝；旧用户迁移前后身份、流量和订阅凭据一致。

### P1：用户管理与套餐管理优化

- [ ] **P1-01 用户列表**：优先展示账号、套餐、剩余流量、有效期、状态；隐藏默认不需要看的协议字段与长凭据。
- [ ] **P1-02 用户详情**：按“账号、服务、订阅、连接配置”分区，解释哪些值来自套餐、哪些是单独调整。
- [ ] **P1-03 常用操作**：提供明确的续期、更换套餐、同步配置、启用/停用和重置密码入口。
- [ ] **P1-04 批量结果**：逐项显示成功、失败和待下发状态；支持只重试失败项，避免把部分成功显示为全部失败。
- [ ] **P1-05 套餐页面**：展示节点分组、额度、有效期、用户数量、启用状态和说明；没有节点时提供明确的下一步入口。
- [ ] **P1-06 套餐变更规则**：将同步配置、换套餐、续期和流量重置分开；操作前显示影响范围，避免无意延期或清零。
- [ ] **P1-07 操作反馈**：提交防重复、加载提示、错误信息、关闭行为和成功后的列表刷新统一处理。

验收标准：管理员不必逐个填写用户节点配置；变更前能理解影响，变更后能看出每个用户的结果；错误重试不会重复创建账号或改变无关数据。

### P2：节点分组与下发管理

- [ ] **P2-01 节点分组模型与页面**：支持创建、编辑节点分组，把多个服务器上的可连接入站组织为一个资源组。
- [ ] **P2-02 套餐引用分组**：一个套餐选择一个或多个节点分组；显示最终包含的节点入站，去重并标记不可用资源。
- [ ] **P2-03 兼容现有套餐**：迁移当前直接保存的入站选择，保持实际连接范围，不扩大用户可访问资源。
- [ ] **P2-04 变更影响与同步**：分组增加或移除节点时，列出受影响套餐和用户，明确同步与失败处理。
- [ ] **P2-05 删除约束**：被套餐引用的分组、被用户使用的套餐需要明确的停用、替换和删除流程。
- [ ] **P2-06 下发状态**：区分配置已保存、等待同步、同步成功、同步失败，保留可定位的错误与重试入口。

验收标准：修改节点分组后，可统一更新相关用户；订阅地址保持不变；旧节点权限能正确撤销；节点失败不会被显示为成功。
